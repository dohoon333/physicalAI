## 1. 개요

`docs/` 폴더의 PRD·체크리스트·전처리 파이프라인 3개 문서는 다수 관점(농업 도메인 전문가, 로보틱스/CV 아키텍트, 문서 정합성 검토, 구조/포맷 검토)의 병렬 리뷰를 거쳐 전면 개정(v2)되었다. 본 보고서는 그중 **현장 조사 체크리스트**와 **데이터 전처리 기법**을 중심으로, 각 항목이 왜 필요하고 실제 전처리 설계와 어떻게 연결되는지를 설명한다.

## 2. 현장 조사 체크리스트 설명

체크리스트(`cherry_tomato_harvest_field_survey_checklist.md`)는 실제 현장(온실)에 나가 전처리 알고리즘 설계에 필요한 정보를 빠르고 객관적으로 기록하기 위한 문서로, A~H 8개 카테고리·총 27개 문항으로 구성된다.

| 카테고리 | 초점 | 문항 수 | 대표 항목 |
| :--- | :--- | :--- | :--- |
| A. 과실(작물) 특성 | 방울토마토 자체의 생물학적 변동성 | 8개 (A-1~A-8) | 품종 구성, 과실 크기, 숙성 색상 패턴, 밀집도, Pedicel 굵기, 표면 광택, **열과(Cracking)**, **기형과(Catface)** |
| B. 재배 환경 | 온실/트러스 구조 | 6개 (B-1~B-6) | 유인방식, 트러스 높이, 통로 폭, 전정 수준, 배치 규칙성, **관수 방식** |
| C. 조명 환경 | 촬영 조건 | 4개 (C-1~C-4) | 피복재, 보광 여부, 조도 변동성, 그림자 패턴 |
| D. 카메라/센서 설치 | 촬영 장비 구성 | 4개 (D-1~D-4) | 센서 구성, 설치 방식, 작업 거리, 렌즈 오염 위험 |
| E. 로봇 작업공간 & 엔드이펙터 | 물리적 접근 제약 | 3개 (E-1~E-3) | 엔드이펙터 구성, 파지 여유공간, 장애물 |
| F. 이동 플랫폼 | 로봇 이동 방식 | 2개 (F-1~F-2) | 레일/AMR, 위치 정밀도 |
| G. 컴퓨팅/네트워크 인프라 | 연산·통신 환경 | 3개 (G-1~G-3) | 처리 위치, 네트워크 상태, 방수/방진 등급 |
| H. 안전/현장 운영 | 운영 정책 | 3개 (H-1~H-3) | 작업자 접근 빈도, 방제 주기, 계절 변동 |

### 2.1 왜 "객관식 체크박스" 형식인가
현장에서 노트북·수첩으로 빠르게 기록할 수 있도록 각 문항을 3~4개의 선택지로 제한했다. 서술형 질문은 현장 작업자가 답하기 번거롭고 후속 분석 시 파싱이 어려운 반면, 체크박스는 즉시 전처리 파라미터(임계값, ROI 크기, 캘리브레이션 방식)로 치환 가능하다.

### 2.2 v2에서 추가된 항목과 그 이유
1차 리뷰(도메인 전문가 검증)에서 아래 리스크 요인이 체크리스트에 전혀 반영되지 않았다는 지적이 있어 3개 항목을 신규 추가했다.

- **A-7 (열과 발생 이력)**: 열과는 방울토마토의 대표적 생리장해로, 표면 균열이 숙성도 판별(색상 기반) 오탐과 손상률 KPI 왜곡을 동시에 유발한다.
- **A-8 (기형과 발생 빈도)**: 벌 수분 부족에 의한 기형과는 파지·절단 결합 포즈 추정이 전제하는 "구형(Sphere)" 가정이 깨지는 대표 케이스라 별도 예외 처리가 필요하다.
- **B-6 (관수 방식)**: 살수 관수는 열과 발생률을 높이고, 물방울로 인한 표면 하이라이트 노이즈를 유발해 전처리 단계(하이라이트 억제)에 직접 영향을 준다.

### 2.3 항목과 전처리 기법의 연결 구조
체크리스트의 모든 문항은 전처리 문서 1장의 "기법 목록" 표에서 최소 1회 이상 인용되도록 설계했다(문서 간 일관성 검토에서 "고아 항목"으로 지적된 A-1·A-2·B-1~3·B-5·D-2·D-4·E-1·F-1~2·G-2~3·H-1~2를 v2에서 모두 연결). 즉, 체크리스트는 "질문지"이고 전처리 문서는 "그 답변이 파이프라인의 어느 단계·기법을 결정하는가"를 명시한 대응표 역할을 한다.

## 3. 데이터 전처리 파이프라인 설명

### 3.1 전체 구조: 공통 → 숙성도 게이트 → 파지·절단 결합 트랙

```
[Stage 0: 공통 전처리]
Sensor Sync → Color/Depth Calibration(선형) → Highlight/Shadow 제거 → 구조물 Masking
   → Denoising → Instance Segmentation(과실/잎/줄기/Pedicel 마스크 확정)
        │
        ▼
[Stage A: 숙성도 판별 게이트]
HSV/Lab 변환 → 품종별 색상 기준 적용 → Multispectral Band Ratio →
부위별 Multi-patch 샘플링·다수결 판정 → 열과/변색/기형과 예외 필터
        │
        ▼  신뢰도 ≥90% & 목표 숙성 단계 통과 시에만
[Stage B: 파지·절단 결합 포즈 트랙]
구(Sphere) 피팅(과실 중심) → Pedicel 축 키포인트 회귀 → 그리퍼-절단날 고정 오프셋 적용
→ 단일 6-DOF 접근 포즈 → 근접 정밀 카메라 2단 재촬영 → Collision-aware 필터링 → MoveIt2 궤적
```

v1 초안에서는 숙성도 판별(Stage A)과 파지 계획(Stage B)을 **병렬 분기**로 그렸으나, 로보틱스 아키텍트 검토에서 두 가지 구조적 결함이 지적되어 v2에서 **직렬 게이트 구조**로 수정했다.

1. **세그멘테이션 공유 문제**: Stage A의 "부위별 색상 샘플링"은 과실 개체 마스크가 있어야 성립하는데, 마스크를 만드는 Instance Segmentation이 Stage B에만 있었다. → v2에서는 세그멘테이션을 Stage 0(공통)로 옮겨 양쪽이 공유한다.
2. **불필요한 연산 낭비**: 숙성도 미달 과실(그린~터닝 단계)은 애초에 수확하지 않으므로 파지·절단 포즈를 계산할 필요가 없다. 병렬 구조는 이 과실들에도 Stage B 연산을 낭비했다. → 직렬 게이트 구조는 Stage A를 통과한 과실에 대해서만 Stage B를 실행해 Edge 연산 부하를 줄인다.

### 3.2 파지점과 절단점을 "하나의 포즈"로 묶은 이유
v1에서는 "과실 파지 위치"와 "Pedicel 절단 각도"를 서로 다른 모델이 독립적으로 추정하도록 설계되어 있었다. 그러나 실제 엔드이펙터는 소프트 그리퍼와 절단날이 하나의 강체로 결합된 복합 모듈이며, 그리퍼와 칼날의 상대적 위치 관계는 로봇이 매번 추정해야 할 변수가 아니라 **하드웨어 제작 시 이미 고정된 상수**다. 두 값을 독립적으로 추정하면:

- 두 추정치가 기구학적으로 서로 모순되는 해(과결정계)가 나올 수 있고,
- 그리퍼로 파지를 마친 뒤에는 절단 위치를 더 이상 보정할 수 없다(파지 순간 이미 접근 궤적이 확정되기 때문).

따라서 v2는 로봇이 실제로 추정해야 할 값을 **"과실 중심 3D 위치"와 "Pedicel 축 방향"** 두 가지로 단순화하고, 여기에 고정된 그리퍼-절단날 오프셋을 적용해 **하나의 6-DOF 접근 포즈**를 산출하도록 재정의했다. 이는 모델 구조를 단순화할 뿐 아니라, 방울토마토처럼 구형에 가까운 소형 과실에는 산업 부품용 GraspNet/AnyGrasp보다 경량 구(Sphere) 피팅이 Edge 연산에 더 적합하다는 판단과도 맞닿아 있다.

### 3.3 절단 정밀도 확보 방식 변경
Pedicel 절단창(과실 상단 5~10mm, 폭 5mm)을 감안하면 애초 목표였던 ±5mm는 절단창 전체 폭과 같아 최악의 경우 과실 어깨를 잘라내는 실패로 이어질 수 있다. 또한 이 정밀도를 Super-resolution(초해상도) 같은 생성적 이미지 기법으로 확보하려던 v1 접근은, SR이 실제로 없는 고주파 디테일을 "그럴듯하게 환각"하는 기법이라 계측값의 신뢰도를 보장할 수 없다는 문제가 있었다.

v2는 두 가지로 대응한다:
1. 목표 정밀도를 물리적으로 달성 가능한 **±2mm**로 재설정.
2. 광역 스캔 카메라(RealSense D435i)로 대상을 확정한 뒤, **근접 정밀 카메라(D405급, 7~50cm 최적 거리)로 2단계 재촬영**하는 광학적 해결로 정밀도를 확보한다. 계측 검증도 레이저트래커(원래 강체 전용 장비라 식물 절단면에는 부적합) 대신 **잔류 Pedicel 길이 캘리퍼 표본계측**으로 변경했다.

### 3.4 숙성도 판별 전처리에서 CLAHE를 제외한 이유
CLAHE(Adaptive Histogram Equalization)는 공간별로 대비를 비선형적으로 확장하는 기법이라 촬영 대상의 절대 색도(hue/saturation 값)를 왜곡시킨다. 그런데 방울토마토 숙성도 판별은 HSV 색공간의 절대적인 색상값 임계치로 단계를 구분하므로, CLAHE를 거친 이미지는 이 임계치 판정 자체를 무효화한다. v2는 CLAHE를 세그멘테이션/기하 처리 트랙 전용으로 한정하고, 숙성도 판별 트랙에는 **절대 색도를 보존하는 선형 캘리브레이션**(노출/게인 정규화, 화이트 레퍼런스 보정)만 적용하도록 분리했다.

### 3.5 Occlusion(가림) 대응과 "환각 형상" 경고
잎에 의한 가림은 PRD 6장에서 영향도·발생 가능성 모두 최고 등급으로 분류된 리스크다. Point Cloud Completion(가려진 형상을 딥러닝으로 복원하는 기법) 자체는 실존하는 접근이지만, 두 가지 한계가 있다: (1) 대부분 강체(Rigid Body) 카테고리로 사전학습되어 있어 연성 과실에 대한 일반화가 검증되지 않았고, (2) 특히 가늘고 얇은 구조인 Pedicel 복원에 취약해 정작 필요한 부위가 복원되지 않을 수 있다. 이 때문에 v2는 완성된 포인트클라우드를 **시각화·참고용으로만** 사용하고, 실제 충돌 회피 판단(Collision Map)에는 절대 반영하지 않도록 명시했다 — 복원 모델이 만들어낸 형상을 근거로 로봇이 접근 경로를 계획하면, 실제로는 없는 공간을 있다고 착각해 충돌할 위험이 있기 때문이다.

### 3.6 데이터 증강 전략 요지
| 증강 기법 | 핵심 목적 |
| :--- | :--- |
| 합성 잎 가림 오버레이 | Occlusion 강건성 |
| 조명/계절 도메인 랜덤화(색상 왜곡 제외) | 조도·색온도 변동 대응, 단 숙성도 라벨과 이미지 색상의 일치는 유지 |
| 밀집도 랜덤화 | 밀집 트러스 대응 |
| Pedicel 굵기/각도 CAD 증강 | 품종별 형태 편차 대응 |
| 절단점 오프셋 증강(±1~3mm) | ±2mm 정밀도 목표에 대한 경계 민감도 완화 |
| 부분 가림 크롭 | 실제 촬영 조건 재현 |
| 기형과/열과 합성 증강 | 초기 단계 예외 클래스 데이터 부족 보완 |
| Sim2Real Fine-tuning | 시뮬레이션-실물 격차 최소화 |

## 4. 전처리 기법 용어 설명

3장에서 사용한 전처리 기법 용어를 처리 목적별로 묶어 설명한다.

### 4.1 센서/이미지 전처리 기법

| 용어 | 설명 |
| :--- | :--- |
| **Sensor Time Sync & Cross-registration** | 서로 다른 센서(RGB-D, 다분광 카메라 등)가 촬영한 프레임의 촬영 시각과 좌표계를 맞추는 작업. 동기화가 안 되면 색상 정보와 깊이 정보가 서로 다른 순간·다른 위치를 가리켜 후속 처리가 전부 어긋난다. |
| **Color Calibration (색상 캘리브레이션)** | ColorChecker 같은 표준 색상표를 기준으로 카메라가 촬영한 색을 실제 색에 맞게 보정하는 작업. 백색 기준점을 맞추는 화이트밸런스가 대표적 하위 기법이다. |
| **선형 노출/게인 정규화** | 카메라의 밝기(노출)·감도(게인) 값을 일정한 비례 관계로 조정하는 것. "선형"이란 색상 간 상대적 비율은 그대로 유지한 채 밝기만 조정한다는 의미로, 절대 색값이 중요한 숙성도 판별에 적합하다. |
| **Specular Highlight(정반사 하이라이트) 억제** | 광택 있는 표면(토마토 껍질 등)에 빛이 그대로 반사되어 생기는 흰색 번짐을 제거하는 처리. 특정 방향의 빛만 통과시키는 편광 필터, 또는 여러 노출값 사진을 합성하는 다중노출 융합으로 구현한다. |
| **Shadow Removal / Illumination Normalization** | 그림자로 부분적으로 어두워진 영역을 보정해 조명 조건과 무관하게 일정한 밝기 분포를 만드는 처리. |
| **Depth Hole-filling** | RGB-D 카메라의 깊이 센서가 반사가 심한 표면이나 경계 부위에서 값을 얻지 못해 생기는 "구멍(결측치)"을 주변 값으로 채워 보완하는 처리. |
| **Bilateral Filtering(양방향 필터링)** | 노이즈는 제거하되 경계선(edge)은 흐려지지 않도록 유지하는 필터링 기법. 위치가 가깝고 값이 비슷한 픽셀일수록 더 큰 가중치를 준다. |
| **Voxel Downsampling** | 3차원 포인트클라우드(점들의 집합)를 일정 크기의 격자(Voxel)로 나눠 격자당 대표 점 하나만 남겨 데이터양과 연산 부하를 줄이는 처리. |
| **Statistical Outlier Removal** | 주변 점들과의 거리가 통계적으로 비정상적으로 먼 점(노이즈로 추정)을 자동 제거하는 포인트클라우드 정제 기법. |
| **Instance Segmentation(인스턴스 세그멘테이션)** | "토마토 영역"처럼 종류만 구분하는 것이 아니라 "이 토마토"와 "저 토마토"처럼 개체 하나하나를 픽셀 단위로 구분하는 기법. YOLOv8-seg, FastSAM, SAM 등이 대표 모델이다. |

### 4.2 숙성도 판별 관련 기법

| 용어 | 설명 |
| :--- | :--- |
| **HSV/Lab 색공간** | 색을 표현하는 좌표계의 종류. RGB(빨강/초록/파랑 조합)와 달리 HSV는 색상·채도·명도를, Lab은 밝기와 색 차이를 사람 눈에 가깝게 분리해 표현해 조명 변화에 덜 민감하게 색을 비교할 수 있다. |
| **Multispectral Band Ratio** | 다분광 카메라가 촬영한 여러 파장대(밴드) 영상 중 두 개 이상의 값을 비율로 계산해 만드는 지표. 식물 상태를 나타내는 NDVI(정규식생지수)가 대표 예이며, 본 프로젝트에서는 숙성 진행도의 보조 지표로 쓴다. |
| **Multi-patch 색상 샘플링** | 과실 전체의 평균색 1개만 보는 대신 여러 부위(패치)에서 각각 색을 샘플링해 부위별로 판정한 뒤 다수결/가중평균으로 최종 판정하는 방식. 얼룩덜룩하게 발색하는 품종 대응에 필요하다. |
| **CLAHE(Contrast Limited Adaptive Histogram Equalization)** | 이미지의 국소 영역별로 명암 대비를 넓혀 어둡거나 밝은 부분의 디테일을 잘 보이게 만드는 기법. 이 과정에서 절대 색상값이 왜곡되므로, 색상 임계값으로 판정하는 숙성도 분류에는 적용하지 않는다(3.4절 참조). |

### 4.3 3D 형상/포즈 추정 기법

| 용어 | 설명 |
| :--- | :--- |
| **Sphere Fitting(구 피팅)** | 3D 점들의 집합에 가장 가까운 구(공 모양)를 수학적으로 계산해 중심 좌표와 반지름을 추정하는 기법. 방울토마토처럼 구형에 가까운 물체의 중심 위치를 가볍고 빠르게 구할 수 있다. |
| **Keypoint Regression(키포인트 회귀)** | 이미지나 3D 데이터에서 특정 의미를 가진 지점(예: Pedicel이 과실에 붙는 지점과 뻗어나가는 방향)의 좌표를 신경망이 직접 예측하도록 학습시키는 기법. |
| **6-DOF(6 Degrees of Freedom, 6자유도)** | 3차원 공간에서 물체의 위치(X·Y·Z 이동)와 방향(회전 3축)을 합쳐 총 6가지 독립 변화 값으로 표현하는 것. 로봇이 특정 지점에 특정 각도로 접근하려면 이 6개 값이 모두 정해져야 한다. |
| **Occlusion(가림/폐색)** | 잎, 줄기, 다른 과실 등에 가려 카메라가 대상의 일부 또는 전체를 보지 못하는 상태. |
| **Point Cloud Completion(포인트클라우드 완성)** | 가려져서 스캔되지 못한 부분의 3D 형상을 딥러닝 모델이 추정해 채워 넣는 기법. 실제로 관측되지 않은 부분을 "그럴듯하게 추측"하는 것이므로, 추측이 틀리면 실제로 없는 공간을 있다고 오판할 위험(환각, Hallucination)이 있다(3.5절 참조). |
| **Super-resolution(초해상도)** | 저해상도 이미지를 고해상도로 변환하는 생성 기법. 화질은 개선되지만 원래 없던 세부 디테일을 모델이 "만들어내는" 것이므로, 정밀한 길이·위치 계측의 근거로는 부적합하다(3.3절 참조). |
| **Collision Map / Collision-aware Filtering** | 로봇 주변 장애물(구조물, 인접 과실 등)의 위치를 3차원 공간에 표시한 지도, 그리고 이 지도를 참고해 충돌 없는 접근 경로 후보만 남기는 필터링 과정. |
| **MoveIt2** | ROS2(로봇 운영체제) 환경에서 로봇 팔의 충돌 회피 경로(궤적)를 계산해주는 오픈소스 로봇 모션 플래닝 프레임워크. |

### 4.4 학습 데이터 증강 기법

| 용어 | 설명 |
| :--- | :--- |
| **Domain Randomization(도메인 랜덤화)** | 시뮬레이션에서 학습 데이터를 만들 때 조명·색상·배치 등 조건을 의도적으로 무작위 변화시켜, 실제 환경의 변동성에도 모델이 잘 대응하도록 만드는 기법. |
| **Sim2Real Fine-tuning** | 시뮬레이션(가상 환경)에서 먼저 모델을 학습시킨 뒤, 실물 환경에서 수집한 소량의 실제 데이터로 마지막 미세 조정을 하는 방식. 시뮬레이션과 실물 사이의 차이(Sim2Real Gap)를 좁히기 위한 절차다. |
| **Hue Jitter(색상 무작위 변형)** | 이미지의 색상(Hue) 값을 학습 시 무작위로 살짝 바꿔주는 증강 기법. 일반적으로는 모델을 강건하게 만들지만, 숙성도처럼 색 자체가 정답의 근거인 작업에 과도하게 적용하면 라벨과 이미지가 불일치하게 되므로 주의가 필요하다(3.6절 참조). |

## 5. 요약 및 향후 검토 사항

- 체크리스트와 전처리 문서는 이제 항목 단위로 1:1 대응되며, PRD v2의 KPI·리스크·용어(Pedicel/Peduncle)와도 정합성이 검증되었다.
- 남은 검토 과제는 PRD 7장에 명시된 **Phase 2 아키텍처 대안(트러스 단위 일괄 수확)**의 Feasibility로, 개체 단위 수확 대비 처리량 이점과 등급 분류 이관 트레이드오프를 비교 검토할 필요가 있다.
- 실제 현장 조사가 완료되면 본 보고서 3장의 임계값(±2mm, 신뢰도 90%, Occlusion 임계치 등)은 체크리스트 응답값 기준으로 재조정해야 한다.
