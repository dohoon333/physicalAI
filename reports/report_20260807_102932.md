## 1. 요약 (Executive Summary)

**최종 1위 — 동적 물체 인터셉트 (1축 리니어 인터셉터).**
추가 부품비 약 19.8만원, 6~8주, 라벨링 0. **3인 심사관 전원이 top4에 올린 유일한 후보**이며, 특히 산출물 심사관은 *"30초 영상 단일 기준이면 이게 1위"*, 하드웨어 심사관은 *"엔지니어링 교육 가치가 전 후보 중 최고"* 로 평가했다.

v1의 1위였던 **컨베이어 숙성도 선별기는 9위로 추락**했다. 자산 재사용이 유일한 차별점이었기 때문이다. 하드웨어 심사관 판정: *"동일 하드웨어 위에서 이상탐지 헤드에 완전히 지배(dominated)된다 — 더 비싼 라벨링(600~1,200장, 3~5시간)으로 더 쉬운 문제를 푸는 버전."*

**가장 중요한 발견**: 서로 다른 관점의 두 심사관이 **독립적으로 동일한 후보 2개에 도달**했다. 하드웨어 심사관의 "적응형 파지력 그리퍼"와 기술정체성 심사관의 "시각-촉각 융합 파지"가 같은 것이고, "1축 리니어 인터셉터"와 "동적 물체 인터셉트"가 같은 것이다. 서로의 후보 목록을 모르는 상태에서 나온 수렴이므로 강한 신호로 취급한다.

## 3. 합의와 이견

### 3.1 만장일치 — 동적 인터셉트

**3인 전원 top4에 올린 유일한 후보.** 다른 어떤 후보도 이 조건을 만족하지 못했다.

| 심사관 | 순위 | 핵심 평가 |
| :--- | :--: | :--- |
| HW | 4위 | *"엔지니어링 교육 가치가 전 후보 중 최고. 반응이 아니라 예측이 필요하고, E2E 지연 예산을 실제로 측정해야만 성공한다."* |
| PAI | 2위 | *"지연 보상을 프로젝트의 중심 문제로 세운 유일한 후보. 오차가 '빗나감'이라는 즉시 관측 가능한 형태로 드러나 학습 피드백이 가장 빠르다."* |
| PROD | 3위 | *"이 후보군 전체에서 최고의 30초다. 화려해서가 아니라 성공/실패가 관객에게 즉시 자명하기 때문."* |

### 3.2 2대1 합의 — 촉각 파지

HW 2위 + PAI 1위 vs PROD 7위. **PROD의 강등 사유가 "N3(인터셉트)와 같은 축인데 영상이 약해서 밀린다"** 이므로, 인터셉트를 1위로 확정하면 이 감점은 순위 경쟁의 결과이지 후보 자체의 결함이 아니다. PROD도 하네스는 **5점 만점**을 줬다.

### 3.3 최대 이견 — 컨베이어 계열

| 심사관 | 판정 |
| :--- | :--- |
| HW 1위 | 이상탐지는 정상 샘플만 필요해 **라벨링이 원리적으로 0**, MVTec AD 공개셋으로 선검증해 **하드웨어 결함과 모델 결함을 분리 디버깅할 수 있는 유일한 후보** |
| PROD 4위 | 과검율↔유출률 트레이드오프 곡선이 `#performance`를 즉시 설득. 13/13 슬롯 충족 |
| PAI 8위 | **폐루프 3점** — *"폐루프 깊이는 추론 헤드가 아니라 액추에이터 자유도와 제어값의 연속성이 결정한다. 최종 출력이 '푸셔를 민다/안 민다' 1-DOF 이진값이다. 헤드를 무엇으로 바꿔도 변하지 않는다."* |

**판정: PAI의 지적이 구조적으로 옳다.** 다만 라벨링 0 · 최저가 · 최저 리스크라는 실용적 강점은 실재하므로 3위로 유지한다. 컨베이어를 살리려면 헤드가 아니라 **액추에이터를 바꿔야** 한다 — 이 관찰이 인터셉트 후보(발화 타이밍을 궤적 계획으로 승격)를 낳았다.

### 3.4 전원 강등 — SO-101 / 로봇팔 계열

GPU 확인으로 **최대 약점(Pi5 추론 2.5~5Hz)이 해소**됐고 서보 ID/영점 지뢰도 공식 도구로 무력화됐음에도 세 심사관 모두 상위권에 올리지 않았다.

- **HW 6위**: **"Pi5도 ESP32도 둘 다 불필요한 유일한 후보"** — 프로젝트 전제와 정면 충돌. LeRobot 표준 워크플로 자체가 팔을 호스트 PC에 USB 직결하는 구조라 Pi5를 끼우는 게 비표준
- **PROD 12위 (16점)**: 도메인이 없어 `#problem`·`#investors`·`도입대상` 3개 슬롯이 백지. 하네스가 두 번째 프로젝트. **실패 시 산출물 0**
- **PAI**: ACT는 N4(SmolVLA)에 흡수, 축② 3점 — *"종단간 정책은 hand-eye를 해결하는 게 아니라 데이터로 덮는다. 실패해도 '빗나갔다'는 정보 하나뿐이라 진단이 불투명하다"*

### 🥇 1위 — 동적 물체 인터셉트 (1축 리니어 인터셉터)

**한 줄**: 고속 카메라 트래킹 → 칼만필터 궤적 예측 → **E2E 지연을 보상한 요격 지점·시각 산출** → 스테퍼 리니어 축이 예측 도달점으로 선이동해 차단/파지

| 항목 | 내용 |
| :--- | :--- |
| 추가 BOM | **198,000원** |
| 기간 | 6~8주 |
| 라벨링 | **0** — HSV + Hough 원 검출로 200+ FPS |
| ESP32 | **필수** — 스텝 펄스 + 사다리꼴 가감속 + E-stop |
| 3D프린터 | 불요 |
| 첫 실패 지점 | **E2E 지연 예산 80~150ms vs 공 도달 500ms.** 측정하지 않으면 "예측 오류"로 오진하지만 실제로는 축이 늦은 것 |

**BOM 상세**: 벨트구동 리니어 액추에이터 키트 400mm(NEMA17 포함) 90,000 / TMC2209 6,000 / **OV9281 글로벌셔터 모듈 35,000** (롤링셔터는 고속 물체가 기울어져 찍힌다) / ESP32 6,000 / 리미트스위치 ×2 3,000 / 24V 4A SMPS 20,000 / 아크릴 테이블·가드·패들 38,000

**선정 이유**
- **3인 전원 top4 — 유일한 만장일치 후보**
- **다른 모든 후보가 구조적으로 못 하는 일을 한다: 시간을 예측한다.** 컨베이어·결함검사·제초·안전정지는 전부 "지금 보이는 것에 반응"하는 시스템이고, 이것만 "미래 위치를 선점"한다
- **지연 보상이 성공/실패를 문자 그대로 가른다.** 캘리브레이션이 틀리면 빗나가고 지연 추정이 틀려도 빗나간다 — 물리 불확실성이 회피 불가능한 1급 문제로 강제된다
- **설명이 필요 없는 데모.** 컨베이어 플리퍼는 "저게 맞는 통인가?"를 설명해야 하지만 낚아채기는 보면 안다
- **스코프 다이얼이 연속적이다.** 축이 느리면 물체를 느리게 하면 된다 — **반드시 성립하는 지점이 존재한다.** 정책 학습(수렴하거나 안 하거나)과 달리 중간 지점이 있다
- **여기서 YOLO는 30FPS라 오히려 부적합하다.** "딥러닝이 정답이 아닌 경우"를 데이터로 보여주는 드문 기회 — 발표에서 강한 챕터가 된다
- 기계 제작 부담이 컨베이어보다 작다 (축 하나 + 경사 레일 vs 컨베이어+진입센서+플리퍼+슈트 4종)

**약점**
- **장르가 바뀐다** (5.1절 참조). `도입 대상` 섹션이 공백이 되고 `#training`이 학습설계에서 실험설계로 성격이 변한다
- `#investors` 숫자는 시장 ROI가 아니라 **ablation delta**로 채워진다 — `지연 보상 없음 4% → 있음 78%`. 지어낸 시장 주장보다 정직하고 더 극적이지만, 기존 페이지 톤과는 다르다
- 실패한 물체가 튀어나가므로 자동 리셋에 홈통 설계 필요

### 🥈 2위 — 적응형 파지력 그리퍼 (시각-촉각 융합 파지)

**한 줄**: 카메라가 물체 식별(달걀/종이컵/나무블록/스펀지) → 목표 파지력 결정 → 승강축 하강 → **ESP32가 힘 피드백 200~500Hz로 목표력까지만 그리퍼를 닫음** → 슬립 감지 시 즉시 재파지 → 파손 없이 이송

| 항목 | 내용 |
| :--- | :--- |
| 추가 BOM | **196,000원** |
| 기간 | 5~7주 |
| **주말 2일 최소동작** | **가능** ← top5 중 유일 |
| 라벨링 | COCO 사전학습으로 **0에서 시작**. 자체 5클래스 승격 시 250장 / 1.5시간 |
| ESP32 | **존재 이유 그 자체** — 200~500Hz 힘 루프는 리눅스 유저스페이스로 불가능 |
| 3D프린터 | 불요 (그리퍼·레일 전량 기성품) |
| 첫 실패 지점 | FSR402 비선형·히스테리시스 → 로드셀 캘리브레이션 필수 |

**BOM 상세**: 메탈 로봇 그리퍼 키트(서보 포함) 30,000 / MG996R 예비 7,000 / **FSR402 ×2 + HX711 5kg 로드셀 세트 14,000** / NEMA17 + 1축 리니어 승강 레일 키트 60,000 / TMC2209 6,000 / USB웹캠 25,000 / ESP32 6,000 / 2020 알루미늄 프로파일 30,000 / 12V 5A SMPS 18,000

**선정 이유**
- **HW 2위 + PAI 1위. 독립 수렴한 두 후보 중 하나**
- **원래 프로젝트를 죽인 "데이터셋 0에서 시작" 문제를 구조적으로 해소하는 유일한 후보.** 로봇이 집어서 들어올려 보면 성공/실패가 자동 판정되므로 **사람 라벨링 없이 self-supervised 데이터가 쌓인다.** 밤새 돌리면 데이터가 모인다
- **하네스가 공짜인 게 아니라 하네스가 이미 시스템 자체다.** 슬립을 감지하려고 이미 읽고 있는 신호가 곧 성공 판정이다. 로봇팔 후보가 하네스 2점을 받은 이유("판정기가 두 번째 프로젝트")와 질적으로 다르다 — PROD도 이 논거를 검증하고 **하네스 5점**으로 상향했다
- **자가 리셋**: 통에 떨어뜨리면 자세까지 랜덤화된다
- **"Pi는 무엇을 얼마나 세게, ESP32는 그 힘의 실현"** 이라는 역할 분담이 발표에서 그대로 설득력이 된다
- **촉각이라는 새로운 축**을 연다 — 다른 후보 전부가 시각 단독이라 포트폴리오 차별성이 크다
- top5 중 유일하게 주말 2일 최소동작

**약점**
- **시각 임팩트 4점.** 슬립→파지력 조절 자체는 밀리미터·서브초라 눈에 안 보인다. **A/B 스플릿 화면(제어 OFF: 종이컵 떨어짐 / ON: 유지)과 "달걀·종이컵을 안 찌그러뜨리고 든다"** 로 살려야 한다 — 그래프가 아니라 샷이 되어야 한다
- `도입 대상` 공백, `#model` 얇음(슬립 분류기가 작다)

### 🥉 3위 — 인라인 결함검사 컨베이어 (무라벨 이상탐지)

**한 줄**: IR 진입 감지 → 정지 → 촬영 → PatchCore 이상탐지 → 불량만 푸셔로 배출 → 도착 통 카운터가 성패 자동 기록

| :--- | :--- |
| 추가 BOM | **143,000원** ← top5 최저가 |
| 기간 | 5~7주 |

| 라벨링 | **구조적으로 0** — 정상 샘플만 필요. 정상품 100~200장 촬영(1시간), 불량은 일부러 흠집 20장(평가용) |

**선정 이유**
- **HW 1위.** 자산 재사용과 무관한 구조적 강점만으로 1위를 지켰다
- **MVTec AD 공개셋으로 파이프라인을 선검증할 수 있어 "모델 문제 vs 내 코드 문제"를 분리 디버깅할 수 있는 유일한 후보.** 초심자에게 이 가치는 크다

- **동일 리그에 헤드만 갈아끼워 데모 3개** — 이상탐지 → 재질분류 → 숙성도. 하드웨어 추가비 0원, 각 1주. **숙성도 헤드는 폐기하지 않고 이 확장 챕터로 남긴다** (원 프로젝트 서사 연결)

- 학습 요소가 얇다

### 4위 — 정밀 조준 제초 살포 (Precision Spot Spraying)

**한 줄**: 갠트리 위 카메라가 지면 촬영 → 작물 vs 잡초 세그멘테이션 → **픽셀 좌표를 노즐 좌표로 변환** → 갠트리 이동 + 솔레노이드 노즐이 잡초에만 정밀 분사 → 명중/오살포 자동 검증. John Deere See & Spray의 탁상 미니어처

| 항목 | 내용 |
| :--- | :--- |
| 추가 BOM | **미확정** (갠트리 조달 경로 미검증) |
| 기간 | 미확정, 8주+ 추정 |
| 라벨링 | 공개셋 존재 (CWFID, DeepWeeds, sugar beet 계열) + 화분 자가 수집 |
| 첫 실패 지점 | **물 + 전자장비 방수**, 그리고 3D프린터 없는 XY 갠트리 조달 |

**선정 이유**
- **PROD 25점 공동 1위.** `제초제 90% 절감`은 **후보 전체에서 유일하게 외부 실증을 인용할 수 있는 숫자**다
- `#problem`이 강력하다: *"제초제의 대부분은 잡초가 없는 땅에 뿌려진다. 광역 살포는 토양·수계·비용을 동시에 태운다"*
- 색소 섞은 물이 **잡초에만 정확히 튀고 작물에는 한 방울도 안 닿는** 30초. 설명 불필요
- 격자 종이 위 화분 배치 → 색소 얼룩 위치를 카메라가 자동 판독 → **완전 무인 채점**
- **픽셀→노즐 좌표변환이 필수**라 hand-eye의 2D 버전을 정면으로 다룬다. 틀리면 작물에 제초제가 튀므로 오차가 즉시 관측된다
- 농업 도메인이라 원 프로젝트의 문제의식이 자연스럽게 이어진다

**4위인 이유 — 검증이 미완이다**
- **하드웨어 심사관의 갠트리·방수 실사가 완료되지 않았다.** 3D프린터 없이 XY 갠트리를 조달하는 경로(저가 CoreXY / 펜플로터 / CNC 키트)와 가격, 물-전자장비 격리 설계가 미확인 상태
- **PROD 본인도 2위로 둔 유일한 이유가 이것**이다: *"물+전자장비 방수와 갠트리 제작은 직전 토마토 프로젝트를 죽인 것과 같은 계열의 빌드 리스크"*
- 기술정체성 심사관의 채점도 받지 못했다
- **갠트리 조달과 방수가 해결되면 1~2위로 올라갈 후보다.** 착수 전 1일 조사로 판별 가능

### 5.1 반드시 인지할 것 — 장르 선택

산출물 심사관이 짚은 구분인데, 이게 실제 의사결정의 본질이다.

| | **제품 페이지 장르** | **연구 데모 장르** |
| :--- | :--- | :--- |
| 해당 후보 | 3위 컨베이어, 4위 제초, 5위 로버 | **1위 인터셉트, 2위 파지** |
| `#problem` | 산업 현실 | 기술 난제 |
| `#investors` | ROI / 인력 감축 % | **ablation delta** (`보상 없음 4% → 있음 78%`) |
| `도입 대상` | 구매자 | **공백** |
| `#training` | 학습설계 (두꺼움) | 실험설계 (얇음) |
| 슬롯 충족 | **13/13** | **12/13** |

**둘 다 유효한 페이지다.** 기존 리포트 3건이 "학습 설계" 장르였으므로, 1·2위로 가면 문서 성격이 바뀐다는 점을 미리 알고 시작해야 한다. 다만 ablation delta는 자가 생성 가능한 실측치라 **지어낸 시장 ROI보다 오히려 정직하다.**

### 5.2 확인해볼 만한 절감 가능성 (미검증)

1·2위 후보가 모두 **1축 리니어 스테이지 + TMC2209 + ESP32**를 쓴다. 인터셉트는 수평축, 그리퍼는 수직 승강축이라는 차이뿐이다. 부품을 재장착해 두 후보를 하나의 축으로 커버할 수 있다면 약 6만원과 조립 1회분이 절감된다. **다만 두 심사관이 각각 별도 BOM으로 산정했으므로 이는 내 관찰이지 검증된 사실이 아니다** — 실제 키트 사양(스트로크, 하중, 장착 인터페이스)을 확인해야 한다.

후보가 아니라 **준비운동**이다. "Pi5 + NCNN export + PCA9685 + 서보 별도전원" 스택을 실물 검증한다. 여기서 배우는 전원 설계(**서보를 Pi 5V 핀에서 급전하면 스톨 2A에 Pi가 리부트되고 SD가 손상된다**)가 이후 모든 후보의 첫 실패 지점을 미리 제거한다. 1~2주.

**본 프로젝트 — 동적 인터셉트 (198,000원)**
착수 첫 주에 **반드시 E2E 지연 예산부터 측정하라.** 카메라 노출 + USB 전송 + 추론 + 시리얼 + 스테퍼 가속을 각각 계측해 합산한다. 이걸 건너뛰면 "예측이 틀렸다"고 오진하지만 실제로는 축이 늦은 것이고, 이 오진에서 빠져나오는 데 몇 주가 걸린다.

**확장 — 적응형 파지력 그리퍼 (196,000원)**
터렛에서 검증한 서보·전원 지식이 그대로 이월된다. 5.2절의 리니어 축 공유가 성립하면 추가비가 더 줄어든다.

3단계 합계 추가 부품비 **약 49만원** (코어 19.8만 별도), 데모 3개.

**단, 하나만 한다면**: 1위 인터셉트 단독으로 충분하다. 3인 만장일치이고 라벨링 0에 6~8주다.

## 9. 최종 결정 — 도메인 제약 반영

### 9.1 추가된 제약

사용자가 **"스마트팩토리 혹은 스마트팜과 관련된 프로젝트"** 를 요청했다. 이는 v2 1위(동적 물체 인터셉트)의 유일한 약점을 정확히 건드린다 — 기술적으로는 3인 만장일치였으나 **도메인이 없어 `#problem`·`#investors`·`도입 대상` 3개 슬롯이 비는 "연구 데모 장르"** 였다 (5.1절).

### 9.2 해법 — 후보 교체가 아니라 도메인 이식

1위 후보의 대상을 **경사 램프의 공 → 움직이는 컨베이어 위의 제품**으로 바꾸면 **컨베이어 트래킹 픽킹(Conveyor Tracking / Picking on the Fly)** 이 된다. 이는 FANUC iRVision Line Tracking, ABB PickMaster 등으로 상용화된 **스마트팩토리 표준 문제**이며, 델타로봇이 식품 포장 라인에서 수행하는 작업이다.

**기술적 본질은 하나도 바뀌지 않는다.**

| | 공 요격 버전 (v2 1위) | 컨베이어 픽킹 버전 (확정) |
| :--- | :--- | :--- |
| 예측 대상 | 굴러오는 공의 도달점 | 벨트 위 제품의 도달점 |
| 지연 보상 | 공 속도 × E2E 지연 | **벨트 속도 × E2E 지연** |
| 위치 추적 | 칼만 필터 | **인코더 태깅 + 칼만** (산업 표준 기법 추가 습득) |
| 실패 관측 | 빗나감 | 빗나감 |
| 스코프 다이얼 | 공을 느리게 | 벨트를 느리게 |

**대신 얻는 것**: 빈 슬롯 3개가 채워지고(`#problem` 정지-검사-재개의 처리량 손실 / `도입 대상` 식품포장·물류분류·전자조립 / `#investors` ablation delta), 3위 결함검사 컨베이어와 **하드웨어를 100% 공유**하여 Phase 2에서 헤드만 교체하면 데모가 하나 더 나온다.

**잃는 것**: 기계 제작 부담 증가(컨베이어 + 인코더 + Z축 + 흡착 추가), 기간 6~8주 → 12~18주(3 Phase 전체).

### 9.3 확정 구성 및 BOM

**MVP 정의**: 2축(X 리니어 + Z 승강) + 진공 흡착. 축이 예측 지점에 **선행 이동하여 대기**하다 물체 도달 시 픽. 속도 매칭은 Phase 1로 분리.

### 9.4 왜 흡착인가 (그리퍼가 아니라)

이동 물체는 접촉 가능 시간이 짧아 그리퍼 클로징 시간을 확보하기 어렵다. 흡착은 접촉 즉시 유지력이 발생한다. 더 중요한 것은 **흡착 압력이 곧 성공 판정 신호**라는 점이다 — 별도 판정기가 필요 없어 자동 채점 커버리지 100%가 성립한다. 이는 v1에서 로봇팔 후보가 하네스 2점을 받은 사유("판정기가 두 번째 프로젝트")를 구조적으로 회피한다.

### 9.5 착수 시 절대 규칙

> **1주차에 지연 예산 계측만 한다. 예측 로직은 작성하지 않는다.**

세 심사관이 공통으로 지목한 최상위 리스크다. 계속 빗나가는 현상을 "예측 알고리즘이 부정확하다"로 오진하고 칼만 필터를 수 주간 튜닝하게 되는데, **실제 원인은 축이 늦게 도착한 것**이다. 카메라 노출·USB 전송·추론·시리얼 왕복 4개 항목을 **개별로** 계측해 히스토그램을 확보한 뒤에야 예측 단계로 넘어간다.

### 9.6 탈락한 도메인 후보

| 후보 | 도메인 | 탈락 사유 |
| :--- | :--- | :--- |
| 정밀 조준 제초 살포 | 🌱 스마트팜 | 산출물 25점 만점 1위이고 `제초제 90% 절감`은 유일한 외부 실증 인용 가능 숫자였으나, **3D프린터 없는 XY 갠트리 조달과 물-전자장비 방수가 미검증**. 직전 토마토 프로젝트를 죽인 것과 같은 계열의 빌드 리스크 |
| 비정지 인라인 결함검사(AOI) | 🏭 스마트팩토리 | 최저 리스크이나 **확정안의 Phase 2로 흡수** — 동일 리그에 헤드만 교체하면 되므로 별도 프로젝트로 둘 이유가 없다 |
| 농산물 선별 컨베이어 | 🌱 스마트팜 | 원 프로젝트 서사 계승도는 최고이나 6클래스 라벨링 600~1,200장(3~5시간) 필요. 확정안의 헤드 교체 챕터로 활용 가능 |
| 위험구역 침입 감지 → 정지 | 🏭 스마트팩토리 | 서사·하네스·비용 최상급이나 시각 3점(정적 그림)으로 30초를 못 채움 |

## 부록 A. Pi5 추론 성능 기준선

Ultralytics 공식 Pi5 벤치 (YOLO26n @640px):

| 포맷 | 추론시간 | FPS |
| :--- | ---: | ---: |
| **NCNN** | **67.03 ms** | **~15** |
| MNN | 91.87 ms | ~11 |
| OpenVINO | 104.55 ms | ~9.6 |
| ONNX | 125.99 ms | ~7.9 |
| PyTorch `.pt` 직행 | 299.09 ms | ~3.3 |

**`.pt` 직행은 3.3 FPS. NCNN export는 선택이 아니라 필수(4.5배).** 320px는 픽셀 1/4 → **YOLOn @320 NCNN = 25~35 FPS.**

기타: MobileNetV3-S INT8 8~15ms / PatchCore(R18@224) 80~150ms / MediaPipe Pose 6.1 FPS / whisper.cpp tiny RTF~0.3 / **OWL-ViT ViT-B/32 3~8초/장 (사용 불가)** / ACT(~80M) Pi5 2.5~5Hz.

**AI 가속기 판정**: top5 중 필수인 것은 **0개**. AI HAT+ 13TOPS(국내 13~15만원)는 단일 스트림 320px 폐루프엔 과잉. Coral USB는 국내 재고 희소 + 런타임 파편화로 비추천.

- **서보 ID/영점 지뢰 무력화 절차**: ①조립 **전에** 12개 ID 설정 + 마스킹테이프 라벨 ②캘리브레이션 JSON을 git 커밋 ③**본 수집 전 2회만 녹화 → 즉시 replay**. 재생이 원본을 따라가면 건전. 안 따라가면 50회가 아니라 2회만 버린다
