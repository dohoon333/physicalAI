# [PRD] 지연 보상 기반 X/Z 컨베이어 트래킹 픽킹 연구 셀

> **문서 성격**: 1인이 4~6주 안에 구축·측정하는 비상용 연구 셀 PRD다. 목표는 제품화나 산업 인증이 아니라, 이동 물체의 미래 접촉 위치를 지연 보상으로 예측할 때의 효과를 정량화하는 것이다.
>
> **MVP 한정**: 단일 클래스, 단일 기계 레인, 단일 고정 배출 빈, 한 번에 하나의 물체만 처리한다. X축은 벨트 진행 방향, Z축은 흡착 높이 방향이다. Y축 구동, 로봇팔, 고전압 장비, 다중 등급·다중 빈·동시 추적은 MVP 범위 밖이다.
>
> **개정 이력**: v2, 설계 검토 반영. 물리 범위, 시간 인과성, 독립 정답 데이터, 동작 예산, 안전 상태와 ablation 절차를 명시.

---

## 1. 개요 및 문제 정의

### 1.1 연구 질문과 가설

이 연구 셀은 컨베이어를 멈추지 않고, 카메라가 본 물체의 미래 위치에 X축 흡착 헤드를 도착시켜 Z축으로 접촉·흡착·상승하는 최소 구성이다. 핵심 질문은 다음과 같다.

> **검출 이후의 통신·계산·기구 동작 지연을 과거 표본으로 추정해 보상하면, 동일한 조건에서 보상하지 않을 때보다 픽 성공률이 높아지는가?**

검출 위치를 현재 위치로 사용하면 헤드가 도착할 때 물체는 이미 전진해 있다. 따라서 접촉 시각의 물체 중심을 예측해야 한다. 이 문서의 **+50 percentage points** 목표는 보장된 결과가 아니라, 고정 조건 ablation으로 검증할 **실험 가설**이다.

### 1.2 물리적 셀과 좌표계

컨베이어 유효 폭은 100~150 mm, 유효 길이는 200~300 mm다. 물체는 지름 또는 한 변 25~50 mm, 무게 5~50 g, 흡착 가능한 매끄러운 평면 또는 완만한 곡면으로 제한한다. 조명은 LED 링라이트와 외광 차단 가드로 고정한다.

| 좌표 또는 값 | 정의 | MVP에서의 사용 |
| :--- | :--- | :--- |
| `(u, v)` | 카메라 픽셀 좌표 | 검출 중심과 레인 적격성 판정 |
| `s` | 벨트 진행 방향 거리 | 물체의 추적 및 접촉 예측 좌표 |
| `y_cam` | 카메라가 환산한 횡방향 위치 | 적격성 확인 전용, 명령 축이 아님 |
| `y_lane` | 기구적으로 고정한 단일 레인의 중심선 | 흡반 중심의 고정 횡방향 위치 |
| `x` | X축의 벨트 진행 방향 위치 | 유일한 수평 명령 축 |
| `z` | 흡반의 수직 위치 | 접근, 접촉, 상승에 사용 |

카메라는 픽셀을 `(s, y_cam)`로 환산한다. 그러나 MVP는 Y축 액추에이터가 없으므로 항상 `y_lane`에서만 동작한다. 레인 허용오차는 캘리브레이션으로 정한 `|y_cam - y_lane| <= 5 mm`다. 이 값은 25 mm 최소 물체와 흡반 접촉 여유를 전제로 한 문서화된 시작값이며, 접촉 위치 검증 결과가 이를 지지하지 않으면 더 좁힌다. 허용오차 밖, 레인 판정 불명, 레인 경계 걸침은 모두 `NO_PICK_LANE`으로 기록하고 물체를 하류로 통과시킨다. 카메라의 `y_cam`은 어떤 경우에도 명령값으로 변환하지 않는다.

레인은 저비용의 수동 가이드로 물리적으로 강제한다. 벨트 위에 진행 방향으로 평행한 두 개의 저마찰 가이드 레일을 최소 150 mm 길이로 고정하고, 레일 안쪽 폭은 시험 단일 클래스의 실제 최대 폭보다 `2~4 mm` 크게 설정한다. 양쪽 레일은 중심 `y_lane`에 대해 같은 거리로 조절하는 슬롯 체결 구조여야 하며, 조절 범위는 27~54 mm다. 능동 구동부는 추가하지 않는다. 각 실험 블록 시작 전 레일의 중심과 폭을 자로 기록한다. acceptance check는 기준 물체 20개를 가이드에 한 번씩 투입해, 픽 구간 영상에서 모든 물체가 `|y_cam - y_lane| <= 5 mm`이고 레일 접촉 정지·끼임이 0건인 것이다. 하나라도 벗어나면 블록은 시작하지 않으며 폭·중심을 재조정한다.

### 1.3 시간, 사건, 클록 도메인

Pi와 카메라는 Pi 단조 시계 `C_Pi`를 사용하고 ESP32는 독립 단조 시계 `C_ESP`를 사용한다. 각 실험 블록 시작 전 30회의 timestamp exchange를 1초 이상에 걸쳐 수행한다. 각 교환은 Pi 송신 `p_send`, ESP32 수신·응답 `e_rx`, `e_tx`, Pi 수신 `p_rx`의 원시 타임스탬프를 남기며, Pi·ESP32 각 중간시각 쌍으로 블록 한정 affine mapping `map_esp_to_pi(e) = a*e + b`를 적합한다. 적합의 절대 residual은 p95가 2 ms 이하이고 최대가 5 ms 이하일 때만 수락한다. 10 cm/s에서 이는 각각 0.2 mm와 0.5 mm의 시간 환산 오차로, ±5 mm 접촉 목표보다 충분히 작다. 매 5분마다 10회 교환으로 같은 한계를 재확인한다. 이 mapping은 사건 상관과 사후 지연 측정에만 쓰며 ESP32의 제어 권한·모션 명령·안전 상태를 바꾸지 않는다. 모든 원시 타임스탬프와 `a`, `b`, residual, mapping ID를 기록한다. 원시 Pi·ESP32 값을 직접 빼는 것은 금지한다.

| 사건 | 필드 | 클록 | 의미 |
| :--- | :--- | :--- | :--- |
| 카메라 노출 시작 | `t_exp_start_pi` | `C_Pi` | 해당 프레임의 물체 위치 기준 시각 `t0` |
| 카메라 수신 완료 | `t_frame_rx_pi` | `C_Pi` | Pi가 프레임을 사용할 수 있는 시각 |
| 검출 완료 | `t_detect_done_pi` | `C_Pi` | `(s0, y_cam)` 산출 완료 시각 |
| Pi 명령 송신 | `t_cmd_tx_pi` | `C_Pi` | 명령을 UART에 기록한 시각 |
| ESP32 명령 수신 | `t_cmd_rx_esp` | `C_ESP` | 명령 프레임 완전 수신 시각 |
| ESP32 X 기동 | `t_x_start_esp` | `C_ESP` | X축 첫 유효 스텝 시각 |
| Pi 환산 X 기동 | `t_x_start_pi_est = map_esp_to_pi(t_x_start_esp)` | `C_Pi` 파생 | 블록 수락 mapping으로 환산한 물리 X축 첫 유효 스텝 시각 |
| Pi X 기동 ACK 수신 | `t_x_start_ack_pi` | `C_Pi` | `command_id`가 일치하는 X 기동 ACK를 Pi가 받은 비동기 진단·전송 사건. 예측기에는 사용하지 않음 |
| ESP32 Z 하강 시작 | `t_z_down_start_esp` | `C_ESP` | X 도착 후 Z 하강의 첫 유효 스텝 시각 |
| ESP32 접촉 스케줄 도달 | `t_contact_sched_esp` | `C_ESP` | Z 프로파일이 접촉 높이에 도달하도록 예약된 시각 |
| ESP32 진공 인가 | `t_vacuum_on_esp` | `C_ESP` | `t_contact_sched_esp` 뒤 밸브를 열기 시작한 시각 |
| 접촉 관측 시각 | `t_contact_obs_pi` | `C_Pi` | 기준 영상에서 물체 중심과 흡반 중심이 같은 접촉 평면에 있는 시각 |
| Z 복귀 완료 | `t_reset_done_esp` | `C_ESP` | 다음 시도 가능 상태의 종료 시각 |

각 프레임의 위치 태그는 `t0 = t_exp_start_pi`에서의 `s0`와 `encoder_count0`이다. 계획의 유일한 기준 시각은 `now = t_cmd_tx_pi`다. 계획 레코드는 명령 직전의 `encoder_count_plan`, `s_est(now) = s0 + encoder_distance(encoder_count_plan - encoder_count0)`, 계산된 `t_contact_pred_pi`, 그리고 그 시각에 도달할 것으로 계산한 `encoder_count_contact_pred`를 함께 기록한다. `encoder_count_contact_pred`는 현재 인코더와 속도 추정으로 만든 **스케줄링 예측값**이며, 미래에 관측한 카운트를 입력으로 사용하지 않는다. `t0`는 모든 지연을 더하는 누적값이 아니라, 해당 물체 위치의 기준 사건이다. 이후 위치는 같은 물체의 태그와 현재 인코더 차이로 계산한다.

`L_k`는 k번째 **완료된 시도 뒤에만** 확정하는 사후 관측 지연이며, 계획 원점 `now` 이후 물리 X축이 실제 기동할 때까지의 Pi 환산 지연으로 `L_k = t_x_start_pi_est - t_cmd_tx_pi`로 기록한다. 따라서 검출·계획에 이미 소비된 시간은 `s_est(now)`에 한 번만 반영되고 `L_k`에 다시 들어가지 않는다. `t_x_start_ack_pi`는 ACK 귀환 전송 지연을 보는 비동기 진단값일 뿐 `L_k`나 접촉 예측에는 사용하지 않는다. ESP32 내부 지연은 `t_x_start_esp - t_cmd_rx_esp`로 별도 기록한다. 교차 도메인 원시값을 직접 빼거나 동일 숫자로 합산하지 않으며, 사건 상관에는 수락된 `map_esp_to_pi`의 파생값만 사용한다. 다음 시도의 스케줄러는 과거 유효 표본만으로 만든 `L_hat_k = percentile({L_i | i < k, valid})`를 사용한다. 초기값은 지연 예산 실험에서 확보한 보수적 p95이며, 현재 시도의 `L_k` 또는 미래 표본을 `L_hat_k`에 넣지 않는다.

시작 후 첫 20개의 유효 지연 표본은 warm-up으로 표시해 KPI와 ablation 분모에서 제외한다. 프레임 타임스탬프 누락, 비단조 증가, 허용 프레임 수명 초과, 명령 식별자 불일치, 인코더 불연속, 또는 수락 mapping 부재는 해당 시도를 `INVALID_TIMESTAMP` 또는 해당 원인으로 `NO_PICK` 처리한다. mapping residual이 p95 2 ms 또는 최대 5 ms를 넘으면 마지막 수락 mapping 이후의 시도는 `INVALID_CLOCK_MAPPING`으로 무효화하고, 해당 블록은 No-Go다. 새 픽은 mapping을 다시 수락할 때까지 금지한다. ACK 누락은 전송 진단으로 기록하되 물리 X 기동의 mapping이 유효하면 예측 표본을 무효화하지 않는다. 실패를 추정값으로 메우거나 마지막 지연값을 재사용해 픽하지 않는다.

### 1.4 예측은 접촉 중심 기준이다

명령 순서는 항상 `X 도착 -> Z 하강 시작 -> Z가 접촉 높이에 도달(t_contact) -> 진공 인가 -> 유지 -> Z 상승`이다. 접촉 시각 `t_contact`는 흡반 중심이 레인 평면의 물체 상면에 도달하도록 Z 하강이 끝나는 시각이며, 진공 인가는 반드시 그 뒤에 시작한다. 기준 영상의 `t_contact_obs_pi`는 이 스케줄 접촉이 실제로 일어났는지 검증하는 관측값이다. 픽 목표는 `x` 목표가 아니라 이 시각의 **물체 중심** `s_contact`다.

```text
s_contact = s0 + encoder_distance(encoder_count_contact_pred - encoder_count0)
          = s_est(now) + v_hat * (L_hat_k + T_x + T_z_down)
t_contact_pred_pi = now + L_hat_k + T_x + T_z_down
x_cmd = map_s_to_x(s_contact)
```

`T_x`는 물리 ESP32 X 기동 `t_x_start_esp`에서 X 도착까지의 검증된 사다리꼴 프로파일 시간이고, `T_z_down`은 안전 높이에서 접촉 높이까지의 Z 하강 시간이다. 따라서 `t_contact_pred_pi = now + L_hat_k + T_x + T_z_down`은 명령 송신부터 물리 X 기동까지의 시간과 그 뒤 전체 X/Z 모션 시간을 정확히 한 번씩 더한다. `T_valve`와 `T_hold`는 접촉 뒤의 흡착 유지 단계이므로 접촉 위치 예측에는 넣지 않는다. 이 식은 `now`에 이미 도달한 위치 `s_est(now)`에서 출발해 `now` 이후 시간만 더한다. `x_cmd`와 `T_x`가 서로 의존하므로 고정점 반복을 최대 5회 수행하고, 수렴하지 않으면 `NO_PICK_NO_CONVERGENCE`로 기록한다. 보상 OFF에서는 같은 추적·기구 모델·게이트를 유지하고, 지연 항만 0으로 둔다. 따라서 비교 대상은 위치 보상뿐이다.

인코더 태깅은 벨트 속도 변동을 추적하는 데 도움을 주지만 벨트 슬립을 없애지 않는다. 롤러 인코더와 실제 벨트 또는 물체 이동이 어긋날 수 있으므로, 매 실험 블록 시작과 엔코더 이상 뒤에는 기준 마크 또는 기준 영상으로 거리 환산을 재검증한다. 허용 범위를 벗어나면 그 블록을 무효화하고 재캘리브레이션한다.

## 2. MVP 흐름과 동작·투입 예산

### 2.1 단일 물체 흐름

1. `READY` 상태에서 물체 한 개가 진입한다. IR 사건과 프레임을 연결하고 `encoder_count0`를 기록한다.
2. HSV 기반 단일 클래스 검출이 `(s0, y_cam)`를 만든다. 레인, 신뢰도, 시간 유효성, 스트로크, 여유 시간, 물체 간격을 모두 통과한 경우만 후보가 된다.
3. 과거 유효 지연 표본으로 `L_hat_k`를 만들고, 접촉 중심 `s_contact`와 `x_cmd`를 계산한다.
4. X축이 안전 Z 높이에서 `x_cmd`로 선행 이동한다. X가 준비되지 않거나 물체가 접촉 창을 지나면 `NO_PICK_MOTION_LATE`로 통과시킨다.
5. 접촉 창에서 Z 하강을 끝내 접촉 높이에 도달한 뒤, 진공 인가, 설정 시간 유지, Z 상승을 순서대로 실행한다. 압력은 장비 상태 진단으로 기록한다.
6. 고정 빈 위에서 진공을 해제하고, X/Z를 다음 시도 안전 위치로 복귀한다. 매 사이클 홈 복귀는 요구하지 않는다. 홈은 BOOT, CALIBRATE, 절대 위치 신뢰 상실, FAULT_STOP 해제 후에만 수행한다.

### 2.2 측정으로 확정할 모션·투입 예산

아래 값은 설계 상한 또는 목표이며, 지연 예산 실험이 끝나기 전의 성능 주장이 아니다. 각 시간은 ESP32 로그에서 실측 p95로 갱신한다.

| 항목 | 예산 또는 규칙 | `NO_PICK` 가드 |
| :--- | :--- | :--- |
| X 선행 이동 `T_x` | 프로파일 모델과 실측 p95 사용, 400 mm 스트로크 안에서만 허용 | 목표가 스트로크 밖, 수렴 실패, 도착 예측이 접촉 창보다 늦음 |
| Z 하강 `T_z_down` | 접촉 높이까지의 실측 p95 | X 준비 전, Z 제한 접근, 접촉 창 부족 |
| 접촉 뒤 진공 인가·유지 `T_valve + T_hold` | `T_z_down` 뒤 밸브 응답과 흡착 유지 시간의 실측 p95 | 압력 센서 이상 또는 시간이 남지 않음 |
| Z 상승 `T_z_up` | 안전 높이까지의 실측 p95 | 상승 제한 이상 또는 위치 신뢰 상실 |
| 고정 빈 배출·복귀 `T_drop + T_reset` | 단일 빈 배출과 다음 안전 위치 복귀의 실측 p95 | 다음 물체의 안전 여유를 침범 |
| 전체 사이클 `T_cycle` | `T_x + T_z_down + T_valve + T_hold + T_z_up + T_drop + T_reset`의 실측 p95 | 다음 적격 물체 도착 전 안전 여유가 없음 |
| 투입 간격 | 연속 픽은 `spacing_time >= T_cycle_p95 + 20% margin`일 때만 허용 | 더 짧으면 후속 물체를 `NO_PICK_SPACING`으로 통과 |

MVP의 10 cm/s, 12 picks/min 목표는 위 `T_cycle`과 간격 조건을 충족할 때만 평가한다. 60 mm라는 고정 거리만으로 연속 픽 가능성을 주장하지 않는다. 속도별로 `spacing_time = spacing_distance / measured_belt_speed`를 산출한다. 한 번에 하나의 물체만 ARMED 또는 PICK 상태가 될 수 있다.

### 2.3 물체 공급과 투입 간격 제어

3.3절은 투입 간격을 ON/OFF 고정 조건으로 요구하고, 3.3절의 표본 요구는 조건당 150개 이상이다. warm-up 20개씩을 더하면 **최소 340회의 투입**이 필요하며, 무개입 가동 목표는 30분이다. 사람이 손으로 하나씩 올리는 방식으로는 이 세 요구를 동시에 만족할 수 없다. 간격이 시도마다 흔들리면 "고정 조건"이 성립하지 않아 ablation의 인과성이 무너진다. 따라서 물체 공급은 기구 요구사항으로 명시한다.

**채택 방식: 순환 슈트 + 계량 게이트(escapement)**

| 구성 | 역할 | 요구사항 |
| :--- | :--- | :--- |
| 배출 빈 → 복귀 슈트 | 픽 성공 물체를 벨트 진입부로 되돌린다 | 중력 경사만 사용, 능동 구동부 없음. 빈을 벨트 시작점보다 높게 배치 |
| 하류 회수 슈트 | `NO_PICK`·실패로 벨트 끝까지 간 물체를 같은 진입부로 되돌린다 | 성공·실패 물체가 같은 진입부로 합류해야 순환이 닫힌다 |
| 계량 게이트 | 진입부에 모인 물체를 **한 번에 하나씩, 고정 주기로** 방출한다 | 서보 1개. ESP32가 `T_release` 주기로 구동. `T_release`는 블록 시작 시 설정·로그하고 블록 중 변경하지 않는다 |
| 게이트 통과 센서 | 실제 방출 시각과 방출 개수를 기록 | IR 1개. 계획 간격과 실제 간격의 편차를 로그로 남긴다 |

`T_release`는 `T_cycle_p95 + 20% margin` 이상으로 설정한다. 게이트가 간격을 강제하므로 `spacing_time`은 설계값이 되고, 실제 편차는 게이트 통과 센서로 측정해 조건 고정이 지켜졌는지 검증한다. 게이트가 두 개를 동시에 방출하거나 방출에 실패하면 `NO_PICK_SPACING` 또는 `FEED_FAULT`로 기록한다.

순환 물체 수는 10~20개로 하고, 블록 시작 전 실제 개수를 기록한다. 순환 경로 전체 통과 시간이 `T_release`보다 짧으면 물체가 진입부에 누적되므로, 누적이 게이트 용량을 넘지 않는 범위에서 개수를 정한다.

> **순환 재사용의 부작용과 완화**: 같은 물체를 반복 사용하면 흡반 자국, 표면 마모, 먼지 부착이 누적되어 후반 시도의 흡착 성공률이 떨어질 수 있다. 이는 시간에 상관된 편향이므로 3.3절의 **block-randomized interleaving이 ON/OFF 간 편향은 상쇄**한다. 다만 절대 성공률은 후반으로 갈수록 낮아질 수 있으므로, 블록마다 물체 상태를 육안 점검하고 오염·손상 물체는 교체한 뒤 교체 사실을 로그에 남긴다. 흡착면은 매 블록 시작 시 청소한다.

수동 투입은 예비 수단으로만 둔다. 게이트 고장 등으로 수동 투입할 경우 해당 블록은 간격 고정 조건을 만족하지 않으므로 **ablation 표본에서 제외**하고 기구 점검용 데이터로만 사용한다.

## 3. 측정, 정답 데이터, KPI

### 3.1 독립 정답 데이터와 수동 주석

예측 접촉 위치와 최종 결과는 제어에 쓰는 카메라·압력·하류 카운터와 독립적으로 검증한다. 기준 장치는 셀 측면 또는 상부에 고정한 별도 기준 영상 장치다. 이 장치는 제어 명령을 내리지 않고, 시험마다 전체 접촉 구간과 빈을 촬영한다. 물체와 흡반에는 대비가 높은 기준 마크를 부착한다.

실무적인 MVP 절차는 다음과 같다.

1. 각 시험 블록의 기준 영상을 저장하고, 프레임의 시간축을 눈에 보이는 LED 플래시 또는 공통 트리거 마커로 로그와 대응시킨다.
2. 실험자 1명은 무작위로 섞인 `trial_id` 목록을 보상 조건을 모른 채 주석한다. 접촉 프레임에서 물체 중심과 흡반 중심을 표시해 `e_contact = s_reference_object - s_reference_cup`를 mm로 환산한다.
3. 같은 기준 영상에서 물체가 흡반과 함께 빈으로 이동해 빈 안에 정지했는지를 보고 `success` 또는 `failure`를 기록한다. `unscorable`은 기준 영상 파일이 없거나 손상됨, 동기 LED 또는 공통 마커가 없어 `trial_id`를 연결할 수 없음, 또는 접촉과 빈 도달의 필수 구간에서 물체나 흡반이 완전히 가려진 경우에만 쓴다. 압력값, 하류 카운터, 저화질이지만 판독 가능한 영상, 혹은 결과가 좋지 않아 보인다는 판단은 `unscorable` 사유가 아니다.
4. 전체 적격 시도의 최소 20%는 두 번째 시점의 재주석 또는 독립 주석자가 반복하고, 불일치는 합의 전 그대로 보존한다. 원시 영상, 주석 파일, 자동 로그의 `trial_id`를 함께 보관한다.

**주석 공수와 드리프트 통제**

주석은 자동화할 수 없는 수작업이며, 로드맵에 별도 작업으로 계상해야 한다. 조건당 150개 이상 × 2조건에 warm-up과 `unscorable`을 더하면 1차 주석 대상은 **340~400건**이고, 20% 재주석을 포함하면 총 **400~480건**이다. 건당 접촉 프레임 탐색과 2점 마킹에 45~60초를 잡으면 **5~8시간**의 순수 주석 시간이 필요하다.

주석자 1명이 이를 연속 처리하면 후반부로 갈수록 판정 기준이 흔들리는 **피로 드리프트**가 발생한다. 블라인드 주석이어도 이 드리프트는 제거되지 않으며, 그 자체가 결과를 오염시키는 교란 변수다. 따라서 다음을 절차로 고정한다.

| 항목 | 규칙 |
| :--- | :--- |
| 세션 분할 | 1회 세션은 최대 60건 또는 60분. 세션 간 최소 15분 휴식 |
| 세션 로그 | 각 주석 레코드에 세션 ID와 세션 내 순번을 기록한다 |
| 재주석 배치 | 20% 재주석은 한곳에 몰지 않고 **서로 다른 세션에 걸쳐** 배치한다. 같은 `trial_id`의 1차·2차 주석은 반드시 다른 세션에 속해야 한다 |
| 드리프트 검출 | 재주석 쌍의 `e_contact` 차이를 세션 순번에 대해 그려 추세가 있는지 확인한다. 유의한 추세가 보이면 해당 구간을 재주석한다 |
| 순서 무작위화 | 주석 목록은 `trial_id` 기준으로 무작위 정렬한다. 시간순·조건순 정렬을 금지한다 |

주석 진행률과 세션 로그는 자동 로그와 함께 보관하며, 주석이 끝나지 않은 조건의 KPI는 보고하지 않는다.

압력과 하류 카운터는 흡반 누설, 물체 낙하, 빈 센서 오동작을 찾는 **진단 교차 확인**이다. 이 신호는 독립 정답도 아니며, 최종 성공률 또는 접촉 위치 오차의 단독 판정 근거가 될 수 없다.

### 3.2 KPI 정의와 판정 분모

| KPI | 목표 또는 가설 | 분자 / 분모와 보고 방식 |
| :--- | :--- | :--- |
| 적격률 | 관찰 지표 | warm-up과 무효 타임스탬프를 제외한 진입 물체 중 모든 사전 게이트를 통과한 수 / 같은 기준의 진입 물체 수 |
| 픽 성공률 | 10 cm/s에서 90% 이상 목표 | 기준 영상에서 `success`인 독립 판정 가능 적격·시도 수 / 독립 판정 가능 적격·시도 수. 조건별 `unscorable`율은 `(unscorable / (independently_scorable + unscorable))`로 별도 보고 |
| 지연 보상 ablation delta | OFF 대비 **+50 percentage points 이상이라는 실험 가설** | `success_rate_ON - success_rate_OFF`, 각 조건의 95% 신뢰구간과 delta의 95% 신뢰구간을 함께 보고 |
| E2E 지연 | 150 ms 이하 목표 | `t_exp_start_pi`부터 Pi가 받은 X 기동 ACK까지의 Pi 도메인 지연. 카메라, 검출, 송신, ACK 구간을 같은 도메인에서 분해해 median, p95, 최대값 보고 |
| ESP32 기동 지연 | 진단 지표 | `t_x_start_esp - t_cmd_rx_esp`의 median, p95, 최대값. Pi 지연과 수치 합산하지 않음 |
| 접촉 위치 예측 오차 | `abs(e_contact) <= 5 mm` 목표 | 기준 영상으로 주석한 판정 가능 시도 중 절대 오차의 median, p95, 5 mm 이내 비율. **부호 있는 `e_contact`의 median과 평균도 함께 보고**해 계통 편향을 노출한다 |
| 유효 처리량 | 12 picks/min 이상 목표 | 기준 영상 `success` 수 / 해당 시험의 벽시계 분. 스킵과 실패도 별도로 제시 |
| 무개입 가동 | 30분 이상 목표 | 사람이 물체 제거, 재시작, 수동 축 이동을 하지 않은 연속 시간. 안전 정지와 복구 횟수 함께 보고 |

성공률, 적격률, 스킵률, 무효율은 분모를 섞지 않는다. 자동 로그는 전량 남기되, 연구의 최종 성과 판정은 독립 기준 영상 주석으로 한다.

### 3.3 공정한 ON/OFF ablation

ON과 OFF는 조명, 단일 물체 클래스, `y_lane`, 레인 허용오차, 흡착 높이, 진공 설정, X/Z 프로파일, 벨트 속도, 투입 간격, 게이트 임계값, 캘리브레이션, 안전 여유를 고정한다. OFF에서는 보상 항만 제거할 뿐 다른 게이트를 느슨하게 하거나 재시도하지 않는다.

조건마다 warm-up 이후 **독립 판정 가능한 적격 시도 최소 150개**를 확보한다. `unscorable`율은 조건마다 5% 이하이어야 하며, 이를 넘으면 해당 조건은 No-Go이고 추가 표본으로 덮어쓰지 않는다. 조건 순서는 시간 경과·온도·마모 편향을 줄이기 위해 짧은 블록 단위로 무작위화해 교차 실행한다. 예를 들어 10개 적격 시도 블록을 ON/OFF로 block-randomized interleaving하고, 각 블록의 실제 속도·온도·압력 진단값을 기록한다. 결측, `unscorable`, 타임스탬프 무효, 안전 fault는 사전에 정한 규칙에 따라 원인별로 보고하며, ON과 OFF에 다르게 제외하지 않는다. 결과에는 조건별 성공률, 95% 신뢰구간, 접촉 오차 분포, 독립 판정 가능 표본 수, `unscorable`율, 제외 사유를 표로 제시한다.

| 구성 | 역할 | MVP 요구사항 |
| :--- | :--- | :--- |
| Raspberry Pi | 카메라 수신, 단일 클래스 검출, 예측, 로그 수집 | `C_Pi` 사건 로그와 명령 식별자 기록 |
| 글로벌 셔터 카메라 | 고정 조명 아래의 물체 중심·레인 적격성 산출 | `t_exp_start_pi` 또는 동등한 노출 기준을 제공 |
| ESP32 | X/Z 모션, 진공 타이밍, 인코더 수집, 안전 상태 | Pi와 독립적인 watchdog, E-stop, `C_ESP` 사건 로그 |

| 저전압 진공 펌프·밸브·압력 센서 | 흡착과 장비 상태 진단 | 압력값은 정답이 아니라 진단 신호 |
| 고정 단일 배출 빈 | 성공 물체를 받는 위치 | 분류 동작이나 등급별 빈은 없음 |
| 순환 슈트와 계량 게이트 | 성공·실패 물체를 진입부로 되돌리고 고정 주기로 하나씩 방출 | 서보 1개와 IR 1개. `T_release`를 블록 시작 시 설정·로그하고 블록 중 변경 금지 |

검출은 고정 조명과 단일 클래스에 맞는 단순 색상·윤곽 기반 방식으로 시작한다. 새 학습 모델이나 추가 ML 요구사항은 MVP에 넣지 않는다. 이전에 언급된 프레임률과 추론 시간 수치는 서로 다른 실행 조건에서 나온 사전 추정치일 뿐, 확정 성능이 아니다. 카메라 수신, 검출, 통신, ESP32 기동, X/Z 동작을 분리한 지연 예산 실험이 끝날 때까지 모든 성능 수치는 **사전 측정 추정치**로만 취급한다.

## 5. 범위와 제외 범위

### 5.1 MVP 범위

- 고정 `y_lane`의 단일 기계 레인과 X/Z 흡착.
- 한 번에 하나의 단일 클래스 물체를 추적·시도하고, 단일 고정 빈에 배출.
- **순환 슈트와 계량 게이트로 강제하는 고정 투입 간격**(2.3절).
- 고정 조명, 글로벌 셔터, IR 진입 태그, 인코더 태깅, 과거 표본 기반 지연 보상.
- 자동 원시 사건 로그, 독립 기준 영상, **세션 분할 블라인드 수동 주석**, ON/OFF ablation.
- ESP32가 담당하는 E-stop, watchdog, 한계 보호와 저전압 구동.

### 5.2 제외 범위

| 항목 | 제외 이유 |
| :--- | :--- |
| Y축 액추에이터와 카메라 y 명령 | MVP는 하나의 기계 레인만 검증한다 |
| 다관절 로봇팔 | IK와 충돌 계획은 지연 보상 연구 질문과 별개다 |
| 동시 추적, 다중 클래스, 다중 등급, 다중 빈 | 물체 할당과 분류를 추가해 ablation의 인과성을 흐린다 |
| 겹친 물체, 다공성·거친 표면 | 단층·이격·흡착 가능 물체라는 연구 경계를 벗어난다 |
| 고속 라인, 상용 안전 인증, 생산 준비성 주장 | 개인 연구 셀의 측정 범위를 넘는다 |
| 매 사이클 홈 복귀 | 회복 시간을 늘려 접촉·투입 예산을 깨뜨린다 |

Phase 1에서만 속도 매칭 픽, 동시 추적, 다중 등급 분류, 다중 빈 배출을 별도 연구 질문과 별도 안전·정답 데이터 설계로 검토한다.

## 6. 안전 상태와 실패 처리

ESP32가 상태 기계를 소유한다. Pi는 요청만 하며, E-stop·통신 상실·제한 위반 시 ESP32의 안전 동작을 우회할 수 없다. 안전 정지는 축 구동을 차단하고 진공을 해제하며, 재개 전 원인 확인과 필요한 재캘리브레이션을 요구한다. 아래 timeout과 임계값은 실험 블록 시작 시 ESP32에 설정하고 원시 로그에 기록한다. 블록 중에는 바꾸지 않는다.

| 상태 | 진입 조건 | 안전 동작 및 다음 상태 |
| :--- | :--- | :--- |
| `BOOT` | 전원 인가 또는 리셋 | 출력 비활성, 진공 해제, 제한·E-stop·센서 자체 점검 후 `CALIBRATE` 또는 `FAULT_STOP` |
| `CALIBRATE` | BOOT, 위치 신뢰 상실, 실험 블록 시작 | 저속 홈과 레인·인코더 거리 재검증. 레인 acceptance check, 압력 센서 범위, 홈 중 하나라도 실패하면 `FAULT_STOP`; 모두 통과하면 `READY` |
| `READY` | 유효 캘리브레이션과 안전 입력 정상 | 안전 Z와 대기 X 유지, 단일 진입만 수락. 적격 후보면 `TRACK`; 마지막 유효 Pi heartbeat 후 300 ms가 지나면 `RECOVER` |
| `TRACK` | 프레임·인코더가 유효한 후보 존재 | 후보 프레임 나이가 100 ms 이하이고 인코더 정상일 때만 `ARMED`. 그 외는 진공 없이 `RECOVER`; heartbeat 300 ms timeout은 `RECOVER` |
| `ARMED` | 접촉 예측과 X 도착 가능성 확인 | X 선행 이동, 접촉 창 감시. 늦음·간격 부족·stale 프레임이면 진공 없이 `RECOVER`. heartbeat 300 ms timeout 또는 인코더 이상이면 즉시 `FAULT_STOP` |
| `PICK` | X 준비 및 접촉 창 도달 | Z 하강 완료 후 진공 인가, 유지, Z 상승. heartbeat 300 ms timeout, 제한, 센서 범위 이상은 즉시 `FAULT_STOP`; 최근 10개 중 세 번째 압력 미달은 즉시 `FAULT_STOP`, 그 외 단일 압력 미달은 진공 해제·안전 Z 상승 후 `RECOVER` |
| `VERIFY` | Z 상승 완료 | 압력과 하류 카운터를 진단값으로 기록, 단일 빈에 배출 후 `RECOVER`. 이 상태의 heartbeat 300 ms timeout은 `FAULT_STOP` |
| `RECOVER` | no-pick 또는 복구 가능 이상 | 안전 Z, 진공 해제, 안전 X로 복귀. 완료 후 heartbeat와 위치 신뢰가 있으면 `READY`, 위치 신뢰가 없으면 `CALIBRATE`, 복귀 제한 위반 또는 heartbeat timeout이면 `FAULT_STOP` |
| `FAULT_STOP` | 심각 이상 또는 E-stop | 모션 차단, 진공 해제, 명령 거부. 수동 원인 확인, E-stop 해제, 재캘리브레이션 뒤에만 `READY` |

| 이상 | 필수 반응 |
| :--- | :--- |
| E-stop | 즉시 `FAULT_STOP`, X/Z 정지, 진공 해제, 자동 재시작 금지 |
| Pi 통신 timeout | Pi heartbeat는 100 ms마다 유효 `trial_id` 또는 keepalive를 보내야 한다. 마지막 유효 heartbeat 후 300 ms가 지나면 `READY`·`TRACK`에서는 새 픽을 금지하고 `RECOVER`; `ARMED`·`PICK`·`VERIFY`·`RECOVER`에서는 즉시 `FAULT_STOP`, 모션 취소, 진공 해제 |
| stale 카메라 또는 타임스탬프 무효 | `TRACK`에서 후보 프레임 나이가 100 ms를 넘거나 사건 순서가 비단조이면 `NO_PICK_STALE_CAMERA`로 기록하고 진공 없이 `RECOVER`. `ARMED` 이후 같은 이상은 `FAULT_STOP` |
| 인코더 이상 | 10 ms 표본에서 카운트 역행, 또는 증가량이 `ceil(1.25 × counts_per_mm × configured_belt_speed_mm_s × 0.010) + 1`보다 크면 이상이다. `TRACK` 이전에는 `CALIBRATE`, `ARMED` 이후에는 즉시 `FAULT_STOP` |
| 압력 이상 | `P_hold`는 `CALIBRATE`에서 설정·로그한 고정 흡착 임계값이다. `t_vacuum_on_esp` 뒤 200 ms 안에 `P_vac <= P_hold`가 아니면 `PRESSURE_MISS`: 진공 해제·안전 Z 상승 후 `RECOVER`한다. 최근 10개 `PICK` 중 `PRESSURE_MISS`가 3개면 세 번째 miss 직후 `FAULT_STOP`한다. 센서값이 50 ms 이상 없거나 연속 3개가 센서 유효 범위를 벗어나면 즉시 `FAULT_STOP`한다 |
| X/Z 소프트 또는 물리 제한 | 즉시 모션 중지, 진공 해제, `FAULT_STOP`, 위치 신뢰 상실로 재홈 필요 |

## 7. 4~6주 로드맵과 MVP Go/No-Go

| 주차 | 산출물 |
| :--- | :--- |
| 1주차 | 사건 스키마, Pi·ESP32 클록 분리 로그, 카메라·통신·기동·모션 지연의 사전 측정 |
| 2주차 | X/Z 기구, 고정 조명, 고정 레인, **순환 슈트·계량 게이트·게이트 통과 센서**, 인코더 거리 환산, 안전 상태 점검 |
| 3주차 | 단일 클래스 검출, 레인 적격성, 인코더 태깅, 접촉 중심 예측, no-pick 정책, **`T_release` 설정과 실제 투입 간격 편차 측정** |
| 4주차 | 단일 물체 X/Z/진공/복귀 시퀀스, 기준 영상 배치와 동기 마커, 수동 주석 절차 확정. **주석 도구와 세션 로그 양식을 이 주차에 완성한다** |
| 5주차 | 고정 조건 ON/OFF block-randomized interleaved 실행, 조건당 독립 판정 가능 적격 시도 150개 이상 확보 |
| 6주차 | **수동 블라인드 주석 400~480건(5~8시간, 세션 분할)**, 재주석 20%와 드리프트 검출, 신뢰구간·제외 사유 포함 측정 보고 |

> 5주차와 6주차를 분리한 이유는 주석이 자동화 불가능한 별도 공수이기 때문이다. 실행과 주석을 같은 주에 묶으면 주석이 밀리거나 세션 분할 규칙이 무너진다.

### MVP Go/No-Go, 여섯 개 게이트

여섯 게이트가 모두 통과할 때만 MVP 결과를 해석한다. 하나라도 실패하면 성공률 목표를 주장하지 않고 원인을 기록한 뒤 해당 게이트부터 보완한다.

| 게이트 | Go 기준 | No-Go 시 조치 |
| :--- | :--- | :--- |
| 1. Y 레인 | 조절 가능한 수동 가이드가 장착되고, 20개 acceptance check에서 모든 물체가 ±5 mm 안에 있으며 끼임이 0건 | 레일 폭·중심을 재조정하고 acceptance check 재실시 |
| 2. 시간 | 블록별 `map_esp_to_pi`가 30회 교환에서 p95 residual 2 ms 이하·최대 5 ms 이하로 수락되고, `t_x_start_pi_est`와 접촉 예측 카운트가 기록되며 `L_hat_k`가 과거 유효 표본만 사용 | mapping·타임스탬프·warm-up 정책을 수정하고 해당 블록을 재측정 |
| 3. 독립 정답 | 기준 영상과 블라인드 수동 주석으로 접촉 오차와 최종 결과를 판정하고, 조건별 `unscorable`율이 5% 이하 | 영상 배치·마커·주석 절차 보완 후 해당 조건을 처음부터 재실험 |
| 4. 모션·투입 예산 | X/Z/진공/복귀 p95와 속도별 간격이 측정되고 no-pick 가드와 수치화된 fault 전이가 적용됨. **계량 게이트가 `T_release` 주기로 하나씩 방출하며, 게이트 통과 센서로 측정한 실제 간격 편차가 설계값 대비 허용 범위 안** | 속도·간격·프로파일 축소 또는 기구 재조정. 게이트 중복·미방출이 반복되면 게이트 재설계 |
| 5. 고정 ablation | 고정 조건, block-randomized interleaving, 조건당 독립 판정 가능 적격 시도 150개 이상, 95% 신뢰구간을 충족 | 표본 추가 또는 조건 드리프트를 제거한 재실험 |
| 6. 주석 무결성 | 400~480건 블라인드 주석이 세션 분할 규칙을 지켜 완료되고, 재주석 20%가 서로 다른 세션에 배치되며, 세션 순번에 대한 유의한 드리프트 추세가 없음 | 드리프트 구간을 재주석. 주석 미완료 조건의 KPI는 보고하지 않음 |

## 8. 성과 해석과 확장 경계

이 연구 셀의 결과는 다음 세 가지로 제한해 해석한다.

1. 과거 지연 표본 기반 보상이 동일 조건에서 성공률과 접촉 위치 오차에 미친 효과.
2. 카메라, 검출, 통신, ESP32 기동, X/Z 동작으로 나눈 지연 예산과 그 변동.
3. 단일 레인·단일 물체·단일 빈 조건에서 측정한 속도, 간격, 안전 복구의 물리적 한계.

이는 상용 라인 처리량, 산업 안전 인증, 다품종 분류 성능을 뜻하지 않는다. Phase 1의 동시 추적, 다중 등급, 다중 빈, 속도 매칭은 이 MVP의 독립 정답 데이터와 안전·동작 예산을 다시 설계한 뒤에만 추가한다. 자동 로그, ESP32 안전 역할, 고정 조명, 인코더 태깅, 그리고 측정된 ON/OFF ablation은 이후 확장의 출발점으로 유지한다.
