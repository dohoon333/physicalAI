# [하드웨어] 지연 보상 X/Z 컨베이어 트래킹 픽킹 연구 셀 — 부품·전원 사양

> **문서 성격**: [conveyor_tracking_picking_prd.md](./conveyor_tracking_picking_prd.md)의 하드웨어 요구를 조달 가능한 부품 단위로 전개하고, 전원 설계를 정리한 문서다.
>
> **⚠ 읽는 법 — 두 종류의 정보가 섞여 있다**
> - **[PRD]** 표시: PRD가 명시한 요구. 절 번호를 함께 적었다. 바꾸려면 PRD를 먼저 고쳐야 한다.
> - **[제안]** 표시: **PRD에 없는 값**이다. PRD의 물리 조건(물체 5~50 g, 벨트 10 cm/s, X 스트로크 400 mm, 저전압 구동)에서 내가 역산한 엔지니어링 기본값이며, **실제 구매 부품의 데이터시트로 반드시 대체해야 한다.**
>
> PRD는 전압·전류를 한 줄도 규정하지 않는다. 이 문서의 모든 전기 수치는 [제안]이다.
>
> **개정 이력**: v1 — PRD 기준 최초 작성.

## 1. 전원 레일 구성

### 1.1 레일 요약

| 레일 | 용도 | 권장 용량 [제안] | 근거 |
| :--- | :--- | :--- | :--- |
| **24 V** | X·Z 스테퍼 2축 | 5 A (120 W) | 스테퍼는 전압이 높을수록 고속 토크가 유지된다. 400 mm 스트로크를 접촉 창 안에 주파하려면 12 V보다 24 V가 유리하다 |
| **12 V** | 진공 펌프, 솔레노이드 밸브, 벨트 모터, 링라이트 | 3 A (36 W) | 24 V에서 벅 컨버터로 강압하거나 별도 어댑터 |
| **5 V (보조)** | 계량 게이트 서보, IR 2개, 인코더, 동기 LED | 2 A (10 W) | **Pi 레일과 물리적으로 분리** (1.3절) |
| **5 V (Pi 전용)** | Raspberry Pi 단독 | Pi 5: 5 A / Pi 4: 3 A | **공식 어댑터 단독 사용. 다른 부하와 절대 공유 금지** |
| **3.3 V** | ESP32 로직, 3.3 V 센서 | ESP32 온보드 레귤레이터 | 서보·모터를 여기서 뽑지 않는다 |

**총 전력 [제안]**: 약 165~190 W. 다만 모든 부하가 동시에 최대로 걸리는 순간은 설계상 존재하지 않는다(X 이동 중에는 진공 인가 전, 진공 유지 중에는 X 정지).

### 1.2 권장 구성 [제안]

```
[AC 220V]
   ├── PSU1  24V 5A (120W)
   │      ├── 24V ──────────────► X 스테퍼 드라이버
   │      ├── 24V ──────────────► Z 스테퍼 드라이버
   │      ├── 벅 → 12V 3A ──────► 펌프 · 밸브 · 벨트모터 · 링라이트
   │      └── 벅 → 5V 2A ───────► 서보 · IR · 인코더 · 동기LED
   │
   └── PSU2  Pi 공식 어댑터 ─────► Raspberry Pi 단독
```

접지는 **한 점(star ground)** 에서 묶는다. ESP32 GND와 스테퍼 드라이버 GND가 이어져 있지 않으면 STEP/DIR 신호의 기준이 없어 탈조·오동작이 난다.

### 1.3 Pi 전원을 분리하는 이유 [제안]

서보는 스톨(stall) 시 정격의 3~5배를 순간적으로 끌어당긴다. Pi의 5 V 핀에서 서보를 급전하면 전압이 순간 강하해 Pi가 언더볼티지로 리부트되고, 최악의 경우 SD 카드가 손상된다. **부하 계산상 여유가 있어 보여도 분리한다** — 문제는 평균 전류가 아니라 과도(transient)다.

**카메라 선택 — 사양보다 중요한 제약 [제안]**

[PRD §4]는 `t_exp_start_pi` **또는 동등한 노출 기준을 제공**할 것을 요구한다. 이건 해상도나 프레임률보다 상위 조건이다.

- **CSI 접속 카메라**도 센서 타임스탬프가 곧 노출 시작 시각인지는 데이터시트·메타데이터로 확인해야 한다. 확정할 수 없으면 외부 트리거 시각을 동등한 노출 기준으로 기록한다.
- **일반 UVC USB 웹캠**은 노출 시작 시각을 노출하지 않는 경우가 많다. 이 경우 `t_exp_start_pi`를 추정할 수밖에 없고, **PRD §1.3의 인과성 규칙이 무너진다.**

→ 구매 전 **노출 타임스탬프 획득 가능 여부를 먼저 확인**한다. 이 항목이 안 되는 카메라는 아무리 사양이 좋아도 이 셀에 쓸 수 없다.

**권장 모델의 인터페이스 주의 [제안]**

- **S1 Raspberry Pi Global Shutter Camera**는 CSI 카메라다. 프레임 메타데이터에 노출 시작 시각이 항상 포함된다고 가정하지 말고, [외부 트리거](https://www.raspberrypi.com/documentation/accessories/camera.html#external-trigger)를 쓸 경우 트리거 발생기의 단조 시각을 노출 기준 시각으로 기록한다.
- **S2 AMT102-V**의 A/B 출력은 5 V CMOS이므로 ESP32 PCNT에 직접 연결하지 않는다. 5 V→3.3 V 레벨 시프터 또는 버퍼를 거친다. 20 mm 아이들러 휠에서 2048 PPR, 4체배 기준 약 0.0077 mm/count이지만 실제 `counts_per_mm`는 조립 후 실측한다.
- **S3/S4 EE-SX671A**는 5 mm 슬롯형 투과 센서다. 물체가 슬롯을 가로지르도록 브래킷을 설계하고, 5 V NPN 오픈 컬렉터 출력은 ESP32 측에서 **3.3 V로 풀업**한다. 센서와 ESP32의 GND는 공통으로 묶는다.
- **S5 MPXV6115VC6U**의 아날로그 출력은 최대 3.3 V를 넘을 수 있으므로 ADC1 앞에 **정밀 분압기를 먼저** 둔다. 버퍼가 필요하면 분압기 뒤에 3.3 V 레일-투-레일 버퍼를 둔다. 흡착 시 절대압이 센서 측정 범위를 벗어나 포화하지 않는지도 구매 전 확인한다.
- **S6 D2F-01L**은 COM–NC를 직렬로 배선한다. 5 V / 4.7 kΩ 풀업 신호를 3.3 V 레벨 변환 뒤 ESP32로 넣어, 정상 닫힘은 Low, 개방·단선은 High(`FAULT_STOP`)가 되게 한다.
- **S7 WP7113ID**는 GPIO에 직결하지 않고 1 kΩ 직렬 저항을 사용한다.

**압력 센서 샘플링 요구 [PRD §6 역산]**

- `t_vacuum_on_esp` 뒤 **200 ms** 안에 임계 도달 판정 → 이 창 안에 충분한 표본이 필요
- **50 ms 이상** 센서값 부재 시 즉시 `FAULT_STOP` → 50 ms보다 빠른 주기로 읽어야 부재를 감지할 수 있다
- → **100~200 Hz 샘플링** [제안]. ESP32 ADC1 채널 사용(ADC2는 WiFi와 충돌)

**인코더 분해능 [제안]**

[PRD §6]의 이상 판정식이 `counts_per_mm`를 직접 쓴다.

```
증가량 한계 = ceil(1.25 × counts_per_mm × 벨트속도[mm/s] × 0.010) + 1
```

접촉 목표가 ±5 mm이므로 인코더 오차는 그보다 한 자릿수 작아야 한다. 권장한 AMT102-V를 2048 PPR로 설정하고 롤러 지름 20 mm(둘레 62.8 mm)에 장착하면, 4체배 8192 counts/rev → **약 130 counts/mm (0.0077 mm/count)** 이다. 실제 `counts_per_mm`와 ESP32 PCNT 신호 여유는 조립 후 벨트 속도에서 실측으로 확인한다.

> **장착 위치 주의**: 구동 롤러에 달면 벨트 슬립이 그대로 오차가 된다. [PRD §1.4]도 슬립이 남는 위험임을 명시한다. **벨트 표면에 눌러 붙인 아이들러 휠**에 인코더를 다는 편이 실제 벨트 이동을 직접 잰다.

**밸브를 3/2로 지정하는 이유 [제안] — 안전 요구에서 역산**

[PRD §6]은 `FAULT_STOP`·E-stop·`RECOVER` 전부에서 **"진공 해제"** 를 요구한다.

- **2/2 밸브**는 유로를 막을 뿐이라, 전원이 끊기면 흡반에 남은 부압이 서서히 빠지며 물체가 늦게 떨어진다 → "해제"가 보장되지 않는다.
- **3/2 밸브**는 비여자 상태에서 흡반을 **대기로 연통**시킬 수 있다.

→ **비여자 = 대기 개방(vent)** 이 되도록 배관한다. 그러면 전원 상실·E-stop·펌웨어 정지 어느 경우든 물리적으로 흡착이 풀린다. **페일세이프가 소프트웨어가 아니라 배관 방향으로 보장된다.**

**서보 스톨 전류 주의 [제안]**

게이트가 물체에 끼이면 서보는 스톨 상태로 최대 전류를 계속 끌어당긴다. 보조 5 V 레일 용량을 스톨 전류 기준으로 잡고, [PRD §2.3]의 `FEED_FAULT`를 감지하면 서보 출력을 끊는 로직을 둔다.

**링라이트 구동 주의 [제안]**

저주파 PWM 조광은 글로벌 셔터의 짧은 노출과 간섭해 프레임마다 밝기가 달라지거나 밴딩이 생긴다. 검출 임계값이 흔들리면 그대로 `NO_PICK` 증가로 나타난다. → **정전류 DC 구동**을 쓰거나, PWM을 쓰더라도 노출 시간보다 훨씬 높은 주파수(수십 kHz)로 건다.

| R2 | 기준 마크 (고대비) | 물체·흡반 중심 표시 | [PRD §3.1] | 스티커 |

> [PRD §3.1] **압력값과 하류 카운터는 진단 신호일 뿐 최종 정답이 아니다.** 성패는 기준 영상의 블라인드 주석으로만 판정한다. 따라서 R1은 "있으면 좋은 것"이 아니라 **KPI 성립 조건**이다.

## 3. E-stop 배선 요구 [제안 — PRD §6 역산]

[PRD §6]은 E-stop 시 "X/Z 정지, 진공 해제, 자동 재시작 금지"를 요구한다. **소프트웨어 신호만으로는 부족하다** — 펌웨어가 멈춰 있으면 신호를 읽을 주체가 없다.

```
E-stop (NC, 래칭)
   ├─ 접점1 ──► 24V·12V 전원 차단 (릴레이 코일 차단 → 모터·펌프·밸브 무전원)
   │              └─ 밸브 비여자 = 대기 개방 → 흡착 물리적 해제
   └─ 접점2 ──► ESP32 GPIO (상태 기록·FAULT_STOP 전이)
```

**NC(평상시 닫힘) 배선을 쓰는 이유**: 배선이 끊어지면 눌린 것과 같은 상태가 되어 안전 측으로 동작한다. NO로 배선하면 단선 시 E-stop이 조용히 무력화된다.

리미트 스위치도 같은 이유로 **NC 직렬**로 묶기를 권한다.

## 4. ESP32 핀 예산 — 확인 필요

| 용도 | 핀 수 |
| :--- | ---: |
| X 스테퍼 STEP / DIR | 2 |
| Z 스테퍼 STEP / DIR | 2 |
| 드라이버 ENABLE (공용 가능) | 1~2 |
| 인코더 A / B (PCNT) | 2 |
| IR 진입 / IR 게이트 | 2 |
| 서보 PWM | 1 |
| 밸브 / 펌프 (MOSFET) | 2 |
| 벨트 모터 PWM / DIR | 2 |
| 압력 센서 (ADC1) | 1 |
| 리미트 스위치 | 2~4 |
| E-stop 보조 접점 | 1 |
| 동기 LED | 1 |
| Pi UART TX / RX | 2 |
| **합계** | **21~24** |

일반 ESP32 DevKit의 실사용 가능 GPIO는 스트래핑 핀·입력 전용 핀을 빼면 여유가 크지 않다. **배선 전에 핀 맵을 확정**하고, 부족하면 다음을 검토한다.

- 리미트 스위치를 축별 **NC 직렬**로 묶어 4핀 → 2핀 (어느 쪽 리미트인지는 잃는다)
- 드라이버 ENABLE 공용화
- I2C GPIO 확장기 사용 — 단, **안전 신호는 확장기에 태우지 않는다** (I2C 지연·행업 시 안전 반응이 늦어진다)
